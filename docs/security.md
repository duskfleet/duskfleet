# What Duskfleet does and does not confine

Duskfleet starts Claude Code as a local child process and records run data locally. The boundaries below describe Duskfleet's implementation; they are not a promise that an unattended run is safe for every project or host. ([`ClaudeCodeExecutor.execute()`](../packages/core/src/execution/claude-code.ts#L201-L207), [run storage schema](../packages/core/src/storage/db.ts#L19-L64), [data directory configuration](configuration.md#configduskfleetyaml))

## Process and environment

The Claude Code child receives the selected project as its working directory. Duskfleet starts it with `shell: false`, passes its arguments directly, and writes the prompt to stdin rather than adding it to the command line. This avoids Duskfleet interpreting the run command through a shell; by default it does not sandbox tools or commands Claude Code is allowed to invoke (an agent can opt in, see [Opt-in sandbox](#opt-in-sandbox-sandbox-true)). ([`ClaudeCodeExecutor.execute()`](../packages/core/src/execution/claude-code.ts#L201-L216), [`buildArgv()`](../packages/core/src/execution/claude-code.ts#L91-L128))

[`childEnv()`](../packages/core/src/execution/child-env.ts#L67-L81) passes the child an allow-list of Duskfleet's process environment, not a copy of it. By default only these reach it: `PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `LANG`, `LC_*`, `TMPDIR`, `TERM`, `TZ`, `ANTHROPIC_*`, `CLAUDE_*`, `NODE_*`, `npm_config_*`, `XDG_*`, and on Windows `SystemRoot`, `windir`, `ComSpec`, `PATHEXT`, `APPDATA`, `LOCALAPPDATA`, `USERPROFILE`, `USERNAME`, `TEMP`, `TMP` (matched without regard to case there). `CLAUDECODE`, `CLAUDE_CODE_ENTRYPOINT`, `CLAUDE_CODE_SSE_*` and `CLAUDE_BIN` are always removed, then `PATH` is adjusted. Everything else (`GITHUB_TOKEN`, `NPM_TOKEN`, `AWS_*`, ...) is dropped. ([`DEFAULT_ENV_ALLOW`](../packages/core/src/execution/child-env.ts#L16-L43), [`childEnv()`](../packages/core/src/execution/child-env.ts#L67-L81))

A run that needs more names it: `claude.env_passthrough` in `config/duskfleet.yaml` applies to every run, an agent's `env_passthrough` frontmatter to that agent's runs, and the two lists are merged. Entries are exact names or `PREFIX_*`. The most common one is `GH_TOKEN` for an agent that uses `gh`. A passed variable is readable by the agent through any tool that prints the environment, so pass only credentials the agent may use. `ANTHROPIC_*` and `CLAUDE_*` are in the default list because Claude Code needs them to authenticate. ([configuration](configuration.md#configduskfleetyaml), [agent frontmatter](agents.md#frontmatter), [`RunManager.startRun()`](../packages/core/src/orchestration/run-manager.ts#L448-L449))

## Project paths and file access

[`validateProjectPath()`](../packages/core/src/orchestration/project-validation.ts#L21-L54) checks that a selected project is an existing directory, refuses the filesystem root and the user's home directory, and—when `allowed_project_roots` is nonempty—refuses project paths outside those roots. The default list is empty, which allows any otherwise-valid project directory. This setting limits which project Duskfleet accepts; it is not an operating-system sandbox for shell commands. ([configuration defaults](configuration.md#configduskfleetyaml), [`validateProjectPath()`](../packages/core/src/orchestration/project-validation.ts#L21-L54))

Duskfleet passes `--permission-prompts none` to unattended Claude Code runs. Its agent documentation says file tools are confined to the project directory unless `add_dirs` widens that scope. Duskfleet passes configured `add_dirs` as `--add-dir`; project-level `add_dirs` apply to every run on that project. ([`buildArgv()`](../packages/core/src/execution/claude-code.ts#L97-L116), [permissions in unattended runs](agents.md#permissions-in-unattended-runs), [project configuration](configuration.md#projects-configprojectsyaml-optional))

## Permissions and command allow-lists

Agent `allowed_tools` and `disallowed_tools` are forwarded to Claude Code as `--allowedTools` and `--disallowedTools`. With `--permission-prompts none`, Duskfleet's agent guide says a tool call not covered by the allow-list is denied and recorded. The allow-list governs Claude Code tool calls; if you allow a shell command or project script, review what that command can do in the project and on the host. ([`buildArgv()`](../packages/core/src/execution/claude-code.ts#L97-L125), [permissions in unattended runs](agents.md#permissions-in-unattended-runs))

## Opt-in sandbox (`sandbox: true`)

The allow-list checks a command's name, not what it does: an allowed `Bash(node:*)` or `Bash(npm test:*)` runs arbitrary code with your privileges. An agent with `sandbox: true` runs its Bash commands inside Claude Code's native sandbox (Seatbelt on macOS, bubblewrap on Linux). Duskfleet passes `--settings '{"sandbox":{"enabled":true,"allowUnsandboxedCommands":false,"network":{"allowedDomains":[...]}}}'`; an agent without the switch gets no `--settings` at all, today's argv. Off by default. ([`sandboxSettings()`](../packages/core/src/execution/sandbox.ts), [`buildArgv()`](../packages/core/src/execution/claude-code.ts))

What was verified with real haiku runs (Claude Code 2.1.325, macOS, the same flags as `buildArgv`):

- **Files**: a write outside the project fails with `EPERM`. `add_dirs` stay writable.
- **Network**: only the hosts in `sandbox_allowed_domains` (exact host names) are reachable, through a local proxy Claude Code starts; every other host is refused. With no list, there is no network at all. A tool that ignores the proxy environment gets no DNS even for a listed host (Node's built-in `fetch` failed with `ENOTFOUND`). Whether `npm install` and `git push` over HTTPS honour the proxy is not verified yet: try the agent once before scheduling it.
- **`gh` on macOS**: with `github.com` and `api.github.com` listed, every `gh` call still fails with `tls: failed to verify certificate: x509: OSStatus -26276`: Go programs verify TLS through a macOS system service the sandbox closes. `sandbox_weaker_network_isolation: true` (see below) fixed it: `gh api`, `gh issue list`, `gh pr view` and `gh auth status` worked, the token read from the keychain, and so did a Node script shelling out to `gh`.
- **Precedence**: `--settings` wins over the project's `.claude/settings.json` in both directions. A project that turns the sandbox on itself keeps it for agents without the switch, because they get no `--settings`.
- **What becomes needs review**: a blocked network connection carries a structured marker in the stream (`tool_result_meta[].remedy.kind: "sandbox_violation"`). Duskfleet counts it (`runs.sandbox_violations`), adds a run note with the denied host, and the run gets the review reason `sandbox_blocked`, because Claude Code still ends it `success` with no permission denial. **A blocked file write has no marker**: it is an ordinary failed command (`EPERM`) and Duskfleet does not detect it, since it never matches error text.

Things that write outside the project and need an `add_dirs` entry (or fail): git worktrees (they write under the main checkout's `.git`), the npm cache (`~/.npm`, or set `npm_config_cache` to a directory under the project). `gh` on macOS needs the key below rather than an `add_dirs` entry (its token came from the keychain). These paths are not verified one by one; check the run's errors the first time.

**Weaker network isolation** (`sandbox_weaker_network_isolation: true`, needs `sandbox: true`, refused otherwise): Duskfleet adds `"enableWeakerNetworkIsolation":true` under `sandbox` in the `--settings` value; without the key the value is byte for byte what it was before. Claude Code documents the setting as letting `gh`, `gcloud` and `terraform` verify TLS inside the sandbox on macOS, and as a weakening of the sandbox's network isolation. It only has an effect on macOS, and it applies to every command of the run, not only to `gh`: turn it on only for agents that need such a tool. The `allowedDomains` list still applies. Not verified: `gh` commands that write (labels, comments, `gh pr create`) and an authenticated `git push` over HTTPS inside the sandbox. A TLS failure inside the sandbox is not detected either: the run ends completed, not needs review.

Platforms: on macOS the sandbox needs `/usr/bin/sandbox-exec` (always present). On Linux it needs `bwrap` and `socat` on the PATH (install `bubblewrap` and `socat`; not verified on Linux yet). Windows has no native sandbox. `duskfleet doctor` reports whether the sandbox is available and which agents use it; on a host without it, every run of a `sandbox: true` agent is refused before anything is spawned, never run unsandboxed. ([`sandboxSupport()`](../packages/core/src/execution/sandbox.ts), [`RunManager.startRun()`](../packages/core/src/orchestration/run-manager.ts))

## Schedule command gates

Command gates are disabled by default (`scheduler.allow_command_gates: false`). When enabled, a gate runs the configured command through `/bin/sh -c` in the project directory, with the same environment allow-list as a run: the defaults, `claude.env_passthrough` and the schedule agent's `env_passthrough`. It runs as a shell command outside Claude Code's tool allow-list. Enable command gates only when you trust the schedule configuration and the callers who can create or change schedules. ([configuration defaults](configuration.md#configduskfleetyaml), [`runCommandGate()`](../packages/core/src/scheduler/gate.ts#L114-L142), [`evaluateGate()`](../packages/core/src/scheduler/gate.ts#L253-L277), [`commandGateRefusal()`](../packages/core/src/scheduler/crud.ts#L120-L128))

## Dashboard

The dashboard's `dev` and `start` scripts bind to `127.0.0.1:4777`. Its middleware accepts Host headers for loopback names and rejects other hosts; the code explicitly describes it as localhost-only with no authentication. Keep it on loopback and do not treat its Host check as user authentication. ([dashboard scripts](../apps/web/package.json#L7-L11), [Host check](../apps/web/lib/host.ts#L1-L14), [middleware](../apps/web/middleware.ts#L4-L10))

## What is recorded

The configured `data_dir` defaults to `../data` relative to the configuration directory and holds the SQLite database and logs. The `runs` table includes the project path, prompt, command, result text, raw result JSON, and log path. Run events are stored as JSON payloads; tool-use summaries and captured Git diffs are among the events Duskfleet records. ([configuration defaults](../packages/core/src/config/loader.ts#L59-L64), [data directory resolution](../packages/core/src/config/loader.ts#L152-L158), [`runs` schema](../packages/core/src/storage/db.ts#L19-L64), [`RunRepository.addEvent()` and `diff()`](../packages/core/src/storage/runs.ts#L492-L526), [tool-use events](../packages/core/src/orchestration/run-manager.ts#L1144-L1152), [`recordDiff()`](../packages/core/src/orchestration/run-manager.ts#L1029-L1033))

The per-run JSONL log receives each child stdout line and tagged stderr; stdout is the Claude Code stream-JSON output. Treat both the database and logs as sensitive project data, and set filesystem access, backup, and retention for `data_dir` to match your needs. ([`buildArgv()` stream-JSON option](../packages/core/src/execution/claude-code.ts#L91-L93), [`ClaudeCodeExecutor.execute()` log writes](../packages/core/src/execution/claude-code.ts#L151-L158), [stdout and stderr logging](../packages/core/src/execution/claude-code.ts#L240-L269), [configured data directory](configuration.md#configduskfleetyaml))

## Recommendations

- Keep `env_passthrough` (global and per agent) to the credentials each agent needs; everything outside the default allow-list stays out of the child unless it is listed there. ([`childEnv()`](../packages/core/src/execution/child-env.ts#L67-L81))
- Set a nonempty `allowed_project_roots` list and review project and agent `add_dirs` entries before unattended use. ([`validateProjectPath()`](../packages/core/src/orchestration/project-validation.ts#L37-L52), [project configuration](configuration.md#projects-configprojectsyaml-optional), [agent configuration](agents.md#frontmatter))
- Keep `scheduler.allow_command_gates` disabled unless the commands and schedule writers are trusted. ([configuration defaults](configuration.md#configduskfleetyaml), [`evaluateGate()`](../packages/core/src/scheduler/gate.ts#L253-L264), [`commandGateRefusal()`](../packages/core/src/scheduler/crud.ts#L120-L128))
- Use an explicit low-cost model while experimenting and configure a maximum budget for agents or runs. ([quick-start warning](../README.md#quick-start), [budget configuration](configuration.md#configduskfleetyaml), [`buildArgv()`](../packages/core/src/execution/claude-code.ts#L121-L125))
- Keep the dashboard bound to loopback; its current Host check does not authenticate users. ([dashboard scripts](../apps/web/package.json#L7-L11), [middleware](../apps/web/middleware.ts#L4-L10))
